What I'm working on

Hi, I'm Mukesh Dewangan.

I'm a Bachelor's student at IIT Gandhinagar, working on machine learning and computer vision. My work spans document intelligence, visual forensics, and computer vision systems built for real-world, imperfect data, not clean benchmarks.

Two questions keep pulling me back:

  • How do we build models that survive real, messy data?
  • How do we combine a few imperfect signals into a decision we'd actually trust?

Right now I'm building a benchmark for AI agents that fix real GitHub issues. See the project →

Where I've worked

Machine Learning Intern
May to Jul 2026
Bank of Baroda, Mumbai · Risk Management Department

Built a PAN card forgery detection pipeline for KYC onboarding: OCR rule checks, tamper detection, visual forensics and a trained patch classifier, combined by majority vote. Tested on 1,284 genuine and 213 forged cards (F1 0.378, patch classifier AUC 0.732). The numbers are modest because the forged set was small and hand made, and the report says so.

Tried several other approaches (error level analysis, DINOv2, LayoutLMv3, PatchCore) that did not work, and wrote up why. Concluded that format-valid single-character edits are likely undetectable from pixels alone. Stress tested a vision-language model (Qwen2-VL-7B), found real signal in only 7 of 340 cases, and kept the simpler design. Also added score calibration and CI/CD, and built an air-gapped document pipeline with a regex and Levenshtein engine for fraud keywords and PDF/CSV audit exports.

Things I've built

01 in progress
repo-issue-agent

A benchmark, and then an agent, for fixing real GitHub issues in Python repositories. So far: 66 verified tasks from marimo, each with a test that fails before the fix and passes after, split into a frozen 20-task dev set and a separate 46-task held-out test set so results can't be tuned on the test data. BM25 and code-aware retrieval are in place, with 44 offline tests and CI. Next: retrieval baselines, a sandboxed tool server (MCP) and the agent loop. No agent results yet.

PAN Card Forgery Detection Pipeline

A four stage document forensics system for a banking risk setting: OCR rules, collar sharpness tamper detection, visual forensics and an EfficientNet-B0 patch classifier, fused by 2-of-4 voting. F1 0.378 on 1,284 genuine and 213 forged cards. The report documents the approaches that failed and why, and where image-only detection runs out.
